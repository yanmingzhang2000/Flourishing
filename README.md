## 现状诊断（已是事实，作为重构动机）

以下结论来自对线上实例（`http://47.93.29.237`，账号只读巡检）的实测，非推测：

- **AI 不在场**：后端 `copilot/chat`、`/execute`、`/process` API 齐备，但主界面导航**无任何 AI 教练入口**；实测 AI 问答为通用套话，**零个性化**（未引用档案/计划/记录）。
- **承诺落差**：用户档案填"30 分钟/次、5 天/周"，实测生成的当日训练**仅 1 个动作 × 2 组（约 5 分钟）**。
- **体验硬伤**：图标大面积缺字形方框、项目卡片文字竖排、日历页"本周 1/3"重复、顶部/底部导航双轨重叠、主题割裂。
- **数据口径 bug**：`completedDays` 同一天返回 3 条、`streak=0`——统计口径疑似把动作当训练，直接伤害激励循环。
- **安全**：生产环境 **HTTP 明文传输 JWT**（无 HTTPS）——已确认需修。

另：代码层面由 Claude 完成的源码级审计（28 项，含 Copilot 状态互踩、零索引、bcrypt 同步阻塞、无备份、游客/登录双实现等）为可信输入，其结论已转化为本基线文档中的"**不得带入新版的债务**"清单（见各文档"反模式 / 红线"小节）。

## 重开发原则

1. **业务知识资产移植，不重写逻辑**：67 条动作库（上线前复核）、训练规则引擎、安全约束、计划生成的确定性约束——逻辑保留，代码可重写。
2. **训练安全是不可绕过的边界**：规则引擎定计划与安全，AI 只解释已确定的计划，不得修改安全决策。
3. **可扩展性优先**：训练域纯函数化、LLM Provider 可替换、DB 层可演进（SQLite→Postgres）、服务无状态、契约先行。
4. **垂直切片交付**：先打通"今日训练→跟练→反馈→下次调整"核心闭环，再扩展日历/成长/复杂 AI。
5. **旧版留作兜底至验收通过**：新版本通过验收前，旧实例保持运行；因用户数据已清空，无数据迁移，切流即替换。

## 关键未决 / 假设

- 目标用户推断为"年轻女性居家塑形"（基于现有内容与文案，待产品确认）。
- "每天 15 分钟"暂按**时间下限卖点**（最低承诺）理解，非产能上限。
- 种子数据：保留经过复核的动作库；用户/训练记录从空开始（不迁移旧数据）。
