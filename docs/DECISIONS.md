## 一、整体结论（先讲判断）

文档完成度高（信息架构、库表、API、页面齐全），但从 V1 演进时**沿用了"AI 万能"的假设**，在科学性、AI 边界、训练科学、数据衔接上有若干方向级问题。经澄清，核心结论：

> **这不是"要不要 AI"的问题，而是"AI 用在哪、不用来哪"的问题。**
> 计划骨架必须确定性（规则/工作流），专业安全靠 RAG 锚定+护栏，LLM 只在约束内做个性化讲解。
> **当前最大风险不是模型，是动作库内容质量**——没有可靠内容，RAG 和 AI 都是空中楼阁。

### §2.3 时长计算（修复公式 bug，决议 4）
原逻辑：
```
基础时长 = 基础项目时长 × 项目数量
建议时长 = 基础时长 × 项目数量 × 1.2   ← 项目数量乘了两次
```
新逻辑：
```
单项目基础时长（见下表，仅主训练，不含热身拉伸）
总时长 = Σ(各项目单项目基础时长) + 固定热身拉伸(建议 5min)
用户微调范围：±5min
```
单项目基础时长统一口径（热身剥离）：

| 项目 | 主训练时长 |
|------|-----------|
| 拜拜肉收紧 | 15min |
| 假胯宽改善 | 20min |
| 下腹收紧 | 15min |
| 斜方肌放松 | 10min |
| 圆肩改善 | 15min |
| 居家基础体能 | 25min |

示例：拜拜肉 + 下腹 → 15 + 15 + 5(热身) = 35min（落回原"25-35"示例区间，且不再爆炸式增长）。

## 三、关键逻辑补丁

### 伤病映射表（决议 6，确定性排除）
```
用户选择(部位) → 展开病症标签 → 排除命中动作
肩 → {shoulder_impingement, rotator_cuff}
肘 → {elbow_pain}
腕 → {wrist_pain}
腰 → {lower_back, sciatica}
膝 → {knee_pain, meniscus}
颈 → {neck_pain}   ← 需先补"颈"选项
```
- **执行层（确定性）**：用户勾选 → 展开标签 → 任何 `contraindications` 交集的动作直接排除（准确率目标 100%）。
- **LLM 层（只解释）**：仅生成"你选了肩伤，XX 动作暂不适合，改用 YY"的解释，不负责判断。

### 难度统一映射（决议 15）
| 用户经验 | 目标难度区间 (1-5) |
|---------|------------------|
| 零基础 | 1-2 |
| 偶尔练 | 2-3 |
| 经常练 | 3-4 |

### 组合去重规则（全身 + 局部）
- 若选中"居家基础体能"且同时选中局部项目，生成计划时对重叠肌群（如手臂/腹）做**单次覆盖提示**，避免同日重复高量刺激。

## 四、目标架构（三层 + co-pilot）

```
用户输入 → [规则/工作流] 计划骨架（天数/组次/排期/时长，确定性）
                ↓
         [RAG] 检索专业约束（禁忌/姿势/进阶），确定性排除危险动作
                ↓
         [LLM] 在约束内生成个性化讲解/鼓励/动作教学（不改动安全与结构）
                ↓
    [co-pilot] 录入期安全向导：硬阻断(安全) + 内联提示(体验)
                ↓
         输出计划 + 评测埋点（禁忌拦截率 / 采纳率 / 完成率）
```

## 五、最大风险与优先级（决议 18）

> **当前第一优先级是"内容管线 + QA"，不是 Agent。**

- 动作库 50-100 条需正确标注肌群/禁忌/难度。来源未定 → 先建内容管线（自有教练 or 公开资料 + 人工校验），建立标注规范与 QA 抽检。
- 没有可靠内容，RAG 检索到的就是错误知识，护栏失效，风险高于无 AI。
- 建议：MVP 先用规则 + 小批量已校验内容跑通闭环，再扩量。

## 六、MVP 范围与阶段建议

- **P0（必做）**：规则计划生成、伤病映射排除、隔天排期、co-pilot 安全向导、合规免责、三层评测基线、已校验动作库（≥30 条）。
- **P1**：LLM 个性化讲解/鼓励、进度分析、内联体验提示、离线评测集扩充。
- **P2**：器械推荐、全量动作库(100 条)、跨设备同步（注册用户）、复盘对话。
