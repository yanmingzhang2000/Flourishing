## 一、项目概述

### 1.1 项目定位
面向女生新手、居家轻器械，主打「局部塑形目标」的健身平台。

### 1.2 核心价值
```
输入个人信息 + 装备 + 目标 → 规则引擎生成计划 → 训练跟练 → 反馈调整
```

### 1.3 与V1本地版的核心差异

| 对比项 | V1 本地版 | V2 网站版 |
|--------|-----------|-----------|
| 数据存储 | 浏览器 localStorage | 服务器数据库 |
| 用户系统 | 无 | 注册/登录/游客 |
| 设备同步 | 不支持 | 支持 |
| 项目数量 | 1个（拜拜肉） | 6个项目 |
| 计划生成 | 硬编码规则 | **规则引擎 + RAG + LLM（仅个性化文案）** |
| 部署方式 | 单HTML文件 | 前后端分离 |

## 二、用户画像与输入维度

### 2.1 目标用户
- **人群**：女生新手
- **场景**：居家/办公室
- **器械**：轻器械或自重
- **需求**：局部塑形（不是全身减脂/增肌）

### 2.2 用户输入维度

#### 维度1：基础信息
| 字段 | 类型 | 选项 | 必填 |
|------|------|------|------|
| 身高 | number | 140-200cm | ✅ |
| 体重 | number | 35-120kg | ✅ |
| 训练经验 | 选择 | 零基础/偶尔练/经常练 | ✅ |
| 伤病情况 | 多选 | 肩/肘/腕/腰/膝/颈 | ❌ |

**伤病标签映射（系统内部）：**
| 用户选项 | 映射到 |
|---------|--------|
| 肩 | shoulder_impingement, rotator_cuff |
| 肘 | elbow_pain |
| 腕 | wrist_pain |
| 腰 | lower_back, sciatica |
| 膝 | knee_pain, meniscus |
| 颈 | neck_pain |

#### 维度2：可用器械

| 类别 | 器械 | 选项 |
|------|------|------|
| **自重** | 无器械 | 任何地方都能练 |
| **哑铃** | 按重量 | 0.5kg / 1kg / 1.5kg / 2kg / 3kg / 5kg |
| **弹力带** | 按阻力 | 轻阻力 / 中阻力 / 重阻力 |
| **弹力绳** | 长款 | 轻 / 中 / 重 |
| **瑜伽垫** | 按厚度 | 6mm / 8mm / 10mm |
| **泡沫轴** | 按类型 | 狼牙棒款 / 普通款 |
| **跳绳** | 按类型 | 负重 / 普通 |
| **壶铃** | 按重量 | 2kg / 4kg / 6kg / 8kg |
| **拉力带** | 门框式 | 模拟高位下拉等器械 |
| **瑜伽砖** | 辅助 | 增加拉伸幅度 |
| **瑜伽球** | 按尺寸 | 55cm / 65cm / 75cm |
| **TRX悬挂带** | 全身训练 | 进阶用户 |

#### 维度3：训练目标（6个项目）

| 项目ID | 名称 | 解决问题 | 目标肌群 | 难度 | 基础时长 |
|--------|------|----------|----------|------|----------|
| tricep_tone | 拜拜肉收紧 | 瘦大臂 | 肱三头肌(主)/前臂(次) | 1-2 | 15min |
| hip_thigh_tone | 假胯宽改善 | 瘦腿提臀 | 臀大肌/臀中肌(主)/股四头肌/腘绳肌(次) | 2-3 | 20min |
| lower_abs_tone | 下腹收紧 | 瘦小肚子 | 腹直肌/腹横肌(主)/腹斜肌(次) | 1-2 | 15min |
| trap_relax | 斜方肌放松 | 舒缓肩颈 | 斜方肌上束(主)/颈肩(次) | 1-2 | 10min |
| round_shoulder_fix | 圆肩改善 | 挺拔体态 | 菱形肌/斜方肌中下束(主)/三角肌后束(次) | 1-2 | 15min |
| full_body_basic | 居家基础体能 | 入门全身 | 多肌群协同 | 2-3 | 25min |

**可多选，时长动态计算：**
```
总时长 = Σ(各项目主训练时长) + 固定热身5min

示例：
- 1个项目（拜拜肉）：15 + 5 = 20min
- 2个项目（拜拜肉+下腹）：15+15 + 5 = 35min
- 3个项目（假胯宽+下腹+圆肩）：20+15+15 + 5 = 55min
```

#### 维度4：每周训练日（用户自选具体哪几天）

```
用户设置：
├── 训练日：勾选具体星期几（周一~周日）
├── 休息日：自动为未勾选的天
└── 可随时调整
```

**恢复规则（48h原则）：**
- 同一肌群训练间隔 ≥ 48小时
- 7天全选时，系统强制插入主动恢复/变式日
- 多项目交替满足恢复要求

#### 维度5：单次训练时长

根据项目数量自动计算，用户可在范围内微调：
```
建议时长 = Σ(各项目主训练时长) + 5min热身
用户可调整范围：±5分钟
```

## 四、多项目组合逻辑

### 4.1 场景分析

**场景1：单项目（如只选"拜拜肉"）**
```
用户选择：拜拜肉 + 每周5天
├── 训练日：5天（全部做拜拜肉动作）
├── 休息日：2天
└── 动作分配：每天5-8个动作，侧重不同角度
```

**场景2：多项目（如选"拜拜肉+下腹"）**
```
用户选择：拜拜肉+下腹 + 每周5天
├── 方案A（默认）：每天组合训练
│   ├── 周一：拜拜肉(10min) + 下腹(8min) + 热身拉伸(5min)
│   ├── 周三：拜拜肉(10min) + 下腹(8min) + 热身拉伸(5min)
│   └── ...
└── AI智能分配比例，避免重复高量
```

### 4.2 AI 组合逻辑

```
AI分析步骤：
1. 识别每个项目的主要/次要肌群
2. 分析动作之间的协同/冲突关系
3. 根据用户器械和经验推荐组合
4. 生成每日动作分配（按比例分配时间）
```

**示例：**
```
项目：拜拜肉(肱三头肌) + 下腹(腹直肌)
器械：哑铃1.5kg

AI分析：
├── 肱三头肌和腹直肌无冲突
├── 可以同一天训练
├── 动作分配（按时间比例）：
│   ├── 热身：5min（全身激活）
│   ├── 拜拜肉：15min（4-5个动作）
│   ├── 下腹：15min（3-4个动作）
│   └── 拉伸：5min（目标肌群）
└── 总时长：40min
```

### 4.3 去重规则

```
当全身项目 + 局部项目组合时：
├── 重叠肌群（如手臂/腹）单次覆盖
├── 不重复高量（手臂类动作总数 ≤ 单项目上限×1.5）
└── 有去重提示字段
```

## 六、动作分配逻辑

### 6.1 根据单次时长分配

| 时长 | 热身 | 主训练 | 拉伸 | 总动作数 |
|------|------|--------|------|----------|
| 15分钟 | 2-3个 | 3-4个 | 2个 | 7-9个 |
| 20分钟 | 3个 | 4-5个 | 2个 | 9-10个 |
| 30分钟 | 3个 | 5-6个 | 3个 | 11-12个 |
| 45分钟 | 4个 | 6-8个 | 3个 | 13-15个 |

### 6.2 根据经验分配

| 经验 | 映射难度 | 组数 | 次数 | 组间休息 |
|------|----------|------|------|----------|
| 零基础 | D1-2 | 2-3组 | 8-12次 | 60秒 |
| 偶尔练 | D2-3 | 3组 | 12-15次 | 45秒 |
| 经常练 | D3-4 | 3-4组 | 15-20次 | 30秒 |

### 6.3 动作筛选规则

```
筛选流程：
1. 根据项目筛选动作池
2. 根据用户器械过滤
3. 根据伤病情况排除危险动作（确定性排除）
4. 根据经验选择难度合适的动作
5. 根据时间比例分配动作数量
6. 生成每日训练计划
```

### 6.4 禁忌排除规则（100%准确率）

```
伤病排除流程：
1. 用户选择伤病选项（如"肩"）
2. 系统映射到内部标签（shoulder_impingement, rotator_cuff）
3. 动作库中所有 contraindications 含上述标签的动作被确定性排除
4. 多伤病叠加时取并集
5. 无伤病时不误杀任何动作
```

## 七、渐进调整策略

### 7.1 阶段划分

| 阶段 | 周数 | 目标 | 调整内容 |
|------|------|------|----------|
| **入门期** | 1-2周 | 学习正确姿势 | 固定动作 |
| **适应期** | 3-4周 | 建立习惯 | 增加次数 |
| **进阶期** | 5-6周 | 提升强度 | 增加组数 |
| **挑战期** | 7-8周 | 突破瓶颈 | 增加难度 |
| **巩固期** | 9-12周 | 稳定成果 | 保持或微调 |

### 7.2 具体调整规则

**如果反馈"太轻松"：**
```
优先级：
1. 增加次数（+2-3次/组）
2. 增加组数（+1组）
3. 增加难度（换高级动作）
注意：不建议同时增加多个变量
```

**如果反馈"太难"：**
```
优先级：
1. 减少次数（-2-3次/组）
2. 减少组数（-1组）
3. 降低难度（换简单动作）
4. 检查是否有伤病风险
```

**如果反馈"关节不适"：**
```
处理流程：
1. 立即停止当前动作
2. 排除该动作及其变式
3. 推荐替代动作
4. 建议休息或就医
```

## 九、数据库设计

### 9.1 核心表结构

```sql
-- 用户表
users (
  id INTEGER PRIMARY KEY,
  email TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
)

-- 用户档案
user_profiles (
  id INTEGER PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  height REAL,
  weight REAL,
  bmi REAL,
  experience TEXT,  -- zero/occasional/regular
  injuries TEXT,    -- JSON数组
  equipment TEXT,   -- JSON数组
  created_at DATETIME
)

-- 项目库
projects (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  target_area TEXT,
  difficulty TEXT,
  duration_minutes INTEGER,
  equipment_needed TEXT  -- JSON数组
)

-- 动作库
exercises (
  id TEXT PRIMARY KEY,
  project_id TEXT REFERENCES projects(id),
  name TEXT NOT NULL,
  primary_muscle TEXT,
  secondary_muscles TEXT,  -- JSON数组
  difficulty INTEGER,      -- 1-5级
  equipment TEXT,          -- JSON数组
  function_primary TEXT,
  function_secondary TEXT,
  contraindications TEXT,  -- JSON数组
  steps TEXT,              -- JSON数组
  tips TEXT,
  warning TEXT
)

-- 用户选定的项目
user_projects (
  id INTEGER PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  project_id TEXT REFERENCES projects(id),
  status TEXT DEFAULT 'active'
)

-- 训练日程（支持用户自选哪几天）
training_schedules (
  id INTEGER PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  week_days TEXT,  -- JSON数组: [1,3,5,6] 表示周一三四六
  created_at DATETIME
)

-- 周训练计划
weekly_plans (
  id INTEGER PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  week_number INTEGER,
  start_date DATE,
  days TEXT,  -- JSON: 完整的周计划结构
  created_at DATETIME
)

-- 训练记录
training_records (
  id INTEGER PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  date DATE,
  day_index INTEGER,
  completed BOOLEAN DEFAULT FALSE,
  feedback TEXT,
  has_joint_pain BOOLEAN DEFAULT FALSE,
  completed_exercises TEXT,  -- JSON数组
  created_at DATETIME
)
```

## 十二、合规边界

### 12.1 禁止承诺
- 不得承诺"局部减脂/只瘦某个部位"
- 脂肪是全身性减少，训练只能增肌紧致
- 动作 function 只能用：紧致/挺拔/放松/激活/改善体态 等表述

### 12.2 安全底线
- 用户提供健身指导，不诊断疾病
- 涉及伤病风险，标注 contraindications 并提示用户咨询医师
- 安全优先：当某个动作对某伤病有不确定风险时，宁可将其加入 contraindications
